Safety

What the AI can do

The session stored by this server grants full control of your Minehut account. The AI can start and stop servers, send console commands with operator privileges, change RAM, read logs and click through the dashboard including billing and plugin settings.

Built-in limits

  • Destructive actions are not automated by default. There is no tool for server reset or account deletion.
  • Console commands only go through minehut_command, which the AI has to call explicitly with the exact command string.
  • The stored session file is created with permissions 600.
  • Login and close tools exist on purpose: you can shut the whole thing down with browser_close.

Recommended practices

  1. Review what you ask the AI to run. A misphrased command like give @e diamond 100000*10000 is exactly as damaging as typing it yourself.
  2. Run the server only on machines you trust. It stores real credentials in your home directory.
  3. Rotate your Minehut password and re-login after any machine compromise.
  4. Do not paste credentials, tokens or session files into support chats or issue trackers.
  5. Turn off the MCP server when you are done for the day. Most clients allow per-project enable and disable.
Operator privileges. Every console command sent through minehut_command runs as the server operator. There is no sandbox between the AI and your server, by design. The AI is a capable assistant with write access, not a read-only viewer.

Account-level precautions

Consider a dedicated Minehut account with fewer privileges, or at least a strong unique password, for any long-running automation setup. The server works with any account, so slotting in a throwaway account costs nothing.
