Authentication

The recommended flow

The Minehut dashboard sits behind Cloudflare, and its session system changes often. Rather than fighting the API directly, the server logs in through a real browser and captures the session for the fast API layer:

  1. Ask your AI to call browser_login_panel with your Minehut email and password.
  2. A browser opens the dashboard and fills the login form automatically.
  3. A Cloudflare challenge or 2FA prompt may appear. Call browser_wait_manual so you can finish it by hand.
  4. The session token is captured and stored in ~/.minehut-mcp/session.json with file permissions 600.
  5. All minehut_* API tools become active. The browser stays available for anything the API does not cover.
Visible window first. Set MINEHUT_HEADLESS=0 in the client config for the first login. Cloudflare challenges are easier for a human to solve in a visible window.

Session storage

Where What
~/.minehut-mcp/session.json The captured token and session id, created with permissions 600 so only your user can read it.
~/.minehut-mcp/browser-profile The persistent browser profile with the dashboard cookies. This is what keeps the browser logged in between runs.
~/.minehut-mcp/shot-*.png Screenshots taken with browser_screenshot.

Authenticating without the browser

The API layer also accepts a session set directly via environment variables:

export MINEHUT_TOKEN="your-token"
export MINEHUT_SESSION_ID="your-session-id"

Tokens found in the browser's local storage (keys such as minehut_auth_token and minehut_session_id) are picked up automatically by browser_wait_manual and by the login flow.

When the session expires

Minehut sessions expire on login, logout or after long inactivity. A rejected session returns a clear error from the API tools that tells the AI to re-run browser_login_panel. The browser profile usually makes the next login a single click, since Cloudflare already trusts the stored cookies.

Treat the token like a password. Anyone with the file contents can control your Minehut account. Do not paste credentials or tokens into public chats, logs or issues.
